# 短剧扒剧本 · 深度还原 Skill（Short-Drama Script Teardown V4.0.1）

> 进场双通道门禁锁 -> 原样扒（逐句 1:1 绑画面） -> 剧本深度还原 -> 骨架分析 -> 离线单页 HTML 交付
> 版本口径：**本包唯一版本号 V4.0.1**（V4.0 的修复版，修了 2 个 P0 / 4 个 P1，逐条见 `CHANGELOG.md`）

## 〇、进场双通道门禁锁（开工第一铁律 · 必先判定「发链接」还是「直接发视频」）

**为什么必须加这道锁？**
「发链接」和「直接发视频文件」在底层信息结构上完全不同：链接自带剧名、简介、预设角色名甚至平台字幕轨；而直接发过来的 `.mp4` 往往是**无剧名、无简介、无角色表、无外挂字幕的「裸视频」**。如果拿处理链接/外挂字幕的逻辑去跑裸视频（只跑 ASR + 每隔十几秒稀疏抽几张图），必然导致**同一个主角因换角度/开特效被拆成四五个名字，或者把逃跑反派的台词安到配角头上**！

### 门禁判定与硬分流规则

1. **未收到素材时（主动询问上锁）**：
   - 若用户只说「帮我扒一部剧 / 还原剧本」但未给素材，**禁止直接盲跑**，必须先问清上锁：
     > 「开工前先确认一下进场通道：你是准备**【A. 发视频链接】**，还是**【B. 直接发视频文件】**？确认后我将按对应通道为你深度还原剧本，并封装成**离线单页 HTML 报告**。」
2. **已收到素材时（自动识别并声明上锁）**：
   - 开工第一行必须显式声明：`【进场门禁已锁定：通道 A（发链接） / 通道 B（直接发视频·裸片强视觉锚定模式）】`。

| 进场通道 | 识别特征 | 核心风险 | 强制执行锁（不同通道走不同规程） |
|---|---|---|---|
| **通道 A：发链接** | 抖音/快手/红果等 URL，或用户给剧名+链接 | 链接失效、需登录、无外挂字幕 | 1. 先抓页面标题/简介/角色表建立《预设角色名册》<br>2. 优先 `yt-dlp --write-subs` 只拉字幕；无字幕则下载后转入通道 B |
| **通道 B：直接发视频** | 用户直接上传 `.mp4/.mov` 视频文件 | **无角色名、说话人极易张冠李戴、一人裂变成多人** | **严禁跨句稀疏抽帧猜人！强制启动下方「裸视频防乱人三把铁锁」**（先通览建唯一人物卡 -> 称谓反向锁名 -> 逐句中点 1:1 绑画面） |

### 能力边界（必读，防止误接活）

- **本包承接**：素材已在手（链接可下载 / 视频已上传）的剧本逆向还原、逐字稿、骨架拆解、HTML 报告封装。
- **本包不承接**：只给一个剧名就让助手去互联网检索、比对、挑选片源的「找剧」活；也不做二创改写与商用成稿。
- **兜底通道（人工听打）**：若 ASR 不可用（无音轨 / 方言过重 / 无字幕轨），走人工听打补录——按 `references/teardown-script-template.md` 第三节边听边填，时间码取整到 0.5s，其余规程与通道 B 完全一致。

## 一、通道 B 专项：直接发视频「防乱人、防乱名」三把铁锁

### 0 号前置闸：视觉能力门禁（三把锁全靠「真看画面」，不许拿文本硬推）

三把铁锁的第一、第三把都要求**真看图**：同人归并看脸与服装，逐句三看看主体/嘴唇开合/神态。所以开工前必须先确认当前模型**能接收图像输入**：

1. **自检一步**：随手 `read` 一张已抽出的帧（或任意 png/jpg）。若返回「Current model does not support images」或类似提示，说明本会话模型是纯文本模型——**图片已被丢包，你根本没看到画面**。
2. **禁止假装三看**：模型不支持图像时，**严禁**靠台词语义、角色名、时间码「推测」说话人和 OS/VO，也严禁把 `待填（看图锁死角色+张闭嘴）` 批量填成`对白`。这是造假稿，比不出稿更坏。
3. **硬停并二选一**：① 切到支持 `text+image` 的模型（需在 `modelPolicy.allow` 白名单内）后重跑；② 转人工：把 `frame_binding_index.md` 与图目录交给用户，由人看图填「张嘴对白 / 闭嘴OS」列，助手只做后续归并。两种都不通就停在那里，不要出半截稿。
4. **读图节奏（控 token）**：一次 `read` 8~12 张，先读「每场首尾帧 + 人物卡候选帧」建唯一人物卡，再逐句读中点头帧；整集逐句读图仅用于**头部全量**集，中段/尾部抽样集只读场级关键帧。

凡进入**【通道 B：直接发视频】**，在给任何一句台词分配说话人之前，必须严格执行以下三把铁锁：

### 第一把锁：全片人物视觉「同人归并锁」（先建唯一人物卡，严禁边看边随手起名）

在拆分台词前，必须先通览全片画面，建立《全集唯一出场人物视觉档案》，并严格执行**「同人特效/状态归并铁律」**：

- **同人归并铁律**：**同一张脸、同一套主体服装**的角色，在全片不同秒位出现以下变化时，**100% 是同一个角色，严禁拆分成多个角色名**：
  1. **瞳色/法相变化**：如常态黑瞳 -> 施法或感知时变成「黄金瞳/红瞳」（严禁拆成两个角色！）。
  2. **本体/特效显露**：如平时收起特效 -> 对敌时展开尾羽/利爪/光效（严禁拆成两个角色！）。
  3. **战损/妆造微调**：如衣衫整洁 -> 吐血染红衣襟、披头散发。
- **同框多角色拆分铁律**：同一镜头或相邻镜头出现 2 个以上角色时，必须分别建档，**严禁把两人的台词合二为一安在同一个人头上**！
- **建档依据必须是图**：人物卡里的「视觉锚点」（脸型/眉形/发型/主体服装/标志配饰）只能来自**实际读过的帧**；没看过图就写「灰衣女子、约 25 岁」＝凭空编造。

### 第二把锁：台词内称谓「反向锁名锁」（有真名/尊称绝不用外貌代称）

1. **首遍扫全集称呼词**：把全集所有直呼其名或尊称的句子挑出来。
2. **称谓合并归一**：通过画面确认指向同一视觉人物后，立即锁定全篇唯一标准角色名。
3. **全局替换禁代称**：一旦锁定标准角色名，全篇从第 1 秒到最后 1 秒统一使用该标准名，**彻底禁用「灰衣女子」「金眼女子」等临时外貌代称**！若某配角全集确实无人叫出姓名，使用「极具辨识度的唯一身份标签」（如 `褐衣随从男`、`黑皮衣寸头男`），且全集叫法绝对统一。

### 第三把锁：逐句时间码「1:1 画面嘴型硬绑定锁」（严禁隔十几秒抽帧瞎猜）

- **逐句中点硬绑定规程**：
  1. 跑完音轨 ASR 拿到每句台词的精确起止时间 `start ~ end` 后，调用 `python scripts/batch_prep.py --bind-frames <视频.mp4> <字幕.srt>`，自动在**每一句台词的正中间秒位 `(start+end)/2`** 抽取 1 张关键帧（或逐句回看视频画面）。
  2. **必须核对抽帧结果**：脚本在索引表 `frame_binding_index.md` 里对没抽到的句子打 `❌ 未抽到帧`，并以退出码 3 报警（V4.0.1 起不再静默成功）。凡出现 ❌ 的句子，**严禁凭记忆补画面**，必须 `--grab-frame` 定点重抽，或核对该句时间码是否落在片长内。
  3. **逐句三看定归属**：
     - **一看画面主体是谁**：该秒画面里是谁在镜头内？
     - **二看嘴唇开合（定对白 vs OS）**：画面内角色嘴唇明显张合 = **现场对白**；画面内角色嘴唇紧闭/定格凝视 = **内心独白（OS）**。
     - **三看声线与混响**：结合音色与空间混响确认归属。
   3. **看图写结论，不写猜测**：逐字稿的「绑定画面帧文件」列必须是真实存在的文件名（与本句同号），「张嘴对白 / 闭嘴OS」列必须基于该帧实际观察；同人归并要求把「同人不同形态」写进备注（如 `同一人·黄金瞳态`），而不是新建角色。

## 二、定位与四段式深度剧本还原交付

本技能专注于**剧本的深度还原**（不输出繁杂的生图/视频分镜提示词），按以下四步交付：

1. **《扒剧逐字稿》**（阶段一 · 原样扒）：输出《出场人物唯一视觉与称谓锁定表》+ 逐句还原台词、时间码、1:1 绑定画面、说话人及画外音（OS/VO）属性。
2. **《深度还原剧本》**（阶段二 · 核心交付）：从逐字稿整理成标准影视级短剧剧本（场号/日夜内外/人物站位/完整 `△` 动作与神态调度/精准对白与 OS/VO 区分/同音错字净稿）。
3. **《骨架分析卡》**（阶段三 · 析骨架）：提炼集粒度节拍表、跨集卡点矩阵、钩子轮换、OS 信息差用法与可迁移公式。
4. **《离线单页 HTML 剧本报告 & CSV》**（阶段四 · 舒适阅读封装）：
   - 将上述成果汇总为**一份结构化 JSON**，字段口径**唯一权威 = `references/data-schema.json`**（`meta / characters / transcript / script_scenes / skeleton` 五块，字段名一字不能改；写错不会报错，只会渲染出空白模块）。
   - 拿不准先生成样例：`python scripts/export_html.py --write-example --out data.json`，然后只改内容、不改字段名。
   - 再出报告：`python scripts/export_html.py data.json --out <剧名_剧本还原报告.html>`，得到**100% 离线可用、单页连续滚动（无分页切换）**的 HTML（顶部悬浮锚点、一键复制整集剧本、导出逐字稿 CSV、打印/转 PDF 强制浅色）。
   - 脚本出稿前做**字段体检**：结构性缺内容直接拒绝出稿（退出码 4），字段缺项逐条打印 `⚠️ 字段体检`，不再静默产出四块空白报告。

## 四、防漏字、纠偏与画外音（OS/VO）四维推导

1. **严禁低帧率稀疏抽帧认字**：默认 `--merge 0` 不吞句；对 ASR 误拆的同一口气碎句结合原音与嘴型合并还原并留痕（V4.0.1 起，被合并的句子必须在逐字稿备注列打 `⤵` 标记，且合并受三重校验约束，不得连锁吞并）。
2. **时间断层自动预警（`--gap-warn 3.5`）**：凡相邻台词间隔 `>= 3.5s`，定点核查是纯打斗/空镜还是漏短句，在 `△` 动作行中如实写出该时间段的动作与调度，不留无解释空白。
3. **三级同音正字纠偏**：建立《专有名词正字表》-> ASR 错字修正留痕 -> 还原剧本净稿交付。
4. **画外音（OS/VO/画外）四维判定**：
   - **闭嘴特写** = `角色名（OS）`
   - **对话流零回应** = `角色名（OS）`
   - **独处张嘴自语** = `角色名`（普通对白，不标 OS）
   - **镜头拍听众/远景** = `角色名（画外）`

## 五、多集扒量与抽样规则（稿头「本集性质」三档定义）

稿头与骨架卡里要填的「本集性质」只有这三档，含义固定：

| 档位 | 定义 | 用途 |
|---|---|---|
| **头部全量** | 前 N 集逐集全量扒（N 由用户定，默认 10~20 集） | 骨架结论的**唯一依据**，跨集卡点矩阵以本档为准 |
| **中段抽样** | 从中间抽 2~3 集 | **只作旁证**，不得单独撑结论；发现规律漂移须提醒用户追加该区段全量 |
| **尾部结局集** | 最后 1~2 集 | 看收尾钩与结局节奏，同样只作旁证 |

统计口径：**结论只认头部全量**；抽样档一旦与头部结论冲突，以头部为准，并在骨架卡里注明冲突点。
